# AI 擬似感情レイヤー（Mood / Inner Voice / Quirk）設計

> 提案対象: `shared/rl/` を使う全学習系体験（基準実装 `apps/arena-shooter/`）
> 関連: `docs/RL_TERRARIUM_REDESIGN_PROPOSAL.md`
> 作成日: 2026-07-30 / 更新: 2026-07-30（共通信号・話し言葉・たまに起きる奇行を反映）
> ステータス: 提案

## 1. 解きたい問題

学習を眺める体験には、**何も起きていないように見える時間**が長く残る。

- 序盤: 失敗が速すぎて、何を学んだのか読み取れない
- 中盤: 生存時間が伸びるほど、画面上の変化は「同じ動きの反復」に見える
- 後半: エピソードが数分になり、GAME OVER 表示の間隔が空く

数値HUD（epsilon、報酬、学習ステップ）は、**すでに理解している人にしか読めない**。
観察者が知りたいのは数値ではなく「今うまくいっているのか」「なぜ今それをしたのか」である。

そこで次の 2 つを追加する。

1. **Mood / Inner Voice** — AI の内部状態を擬似的な気分として翻訳し、話し言葉で出力する（常時、ただし控えめ）
2. **Quirk（奇行）** — **たまに**、台詞と同時に説明のつかない行動を取る。観察の山場を作る（§6）

2 は毎回起きてはいけない。**滅多に起きないから見どころになる。**

## 2. 設計原則

### 2.1 擬似的でよいが、嘘はつかない

気分は演出だが、**必ず実測値から導出する**。ランダムな台詞や、雰囲気だけの
感情アニメーションは入れない。

- すべてのムード遷移は、閾値付きの数値条件に対応する
- すべての台詞は、そのとき成立した条件とセットで保持する
- デバッグ表示で、台詞の根拠となった数値を出せる

奇行も同じ。**観察者には不可解に見えるが、内部的には必ず理由がある。**
理由は後から明かす（§6.4）。

### 2.2 方策への干渉は Quirk 1本に集約する

気分がにじみ出て常時じわじわ行動が変わる、という作りは避ける。
成績が動いた理由が追えなくなるためである。

Mood は**読み出し専用**。方策・Q値更新に触れるのは、明示的に発火した Quirk の最中だけ。

### 2.3 沈黙が既定

常時しゃべる AI はノイズになる。**黙っているのが普通で、事件が起きたときだけ話す**。
上達するほど静かになる。この静けさ自体が上達の表現になる。

## 3. 入力信号 — 全ゲーム共通で取る

**ゲームごとに定義を書き足さなくても成立すること**を要件にする。
`threat` や「死因」をゲーム固有に定義させると、横展開のたびに設計判断が発生して止まる。

そこで信号はすべて、**エージェントとエピソード履歴だけから**導出する。

### 3.1 エージェント由来（`shared/rl/` 内で完結）

| 信号 | 導出 | 意味 |
|---|---|---|
| `epsilon` | 既存 | 探索率 |
| `exploratory` | 既存 | 今の1手が思いつきか |
| `tdErrorAverage` | `observe()` 内で計算済みの TD誤差の指数移動平均（半減期 ≈200 step） | 驚き・予想外さ |
| `margin` | `decide()` の許可行動内で 最良Q − 次点Q | 迷いのなさ |
| `newStateRate` | 直近 200 step 中、初出だった状態の割合 | 未知の状況にいるか |
| `valueDrop` | 直近 30 step の `qValue` の傾き（負ほど悪化） | **これが共通版の `threat`** |
| `visitCounts` | 状態 × 行動の訪問回数（新規。§6.3 で使う） | どこを試していないか |

`valueDrop` が要点。HP や敵密度といったゲーム固有の危険度を定義しなくても、
**「AI 自身の見込みが下がり続けている」= 追い込まれている**として共通に扱える。
むしろ AI の主観に沿う分、擬似感情としてはこちらが正しい。

### 3.2 エピソード履歴由来（共通アダプタ）

| 信号 | 導出 |
|---|---|
| `survivalSeconds` / `survivalMedian` / `survivalBest` | エピソード長の履歴（直近20件） |
| `rewardTrend` | エピソード総報酬の傾き |
| `failureSignature` | **終端直前の `encodeState()` キー** |

`failureSignature` が 2 つめの要点。死因タグをゲーム側に書かせず、
**「どんな状態で終わったか」の状態キーそのもの**を死因の代理にする。
直近 5 エピソードで同じキーが 3 回以上出れば「同じところで死んでいる」と判定できる。
`encodeState` は全ゲームが必ず持つので、追加実装は不要。

### 3.3 結果として、ゲーム側の追加実装はゼロ

Mood レイヤーは `TabularQAgent` インスタンスとエピソード境界イベントだけを受け取る。

```ts
const mood = new MoodTracker(agent);   // これだけで全ゲームで動く
mood.endEpisode(survivalSeconds, totalReward);
```

### 3.4 `TabularQAgent` への追加（前提作業）

`shared/rl/tabular_q_agent.ts:62` はすでに TD誤差を計算して捨てている。公開するだけでよい。

```ts
readonly tdErrorAverage: number;     // TD誤差の指数移動平均
readonly newStateRate: number;       // 直近200step の初出率
lastTerminalStateKey: string | null; // finishEpisode 時の previousState
```

`TabularDecision`（`shared/rl/rl_types.ts`）に `margin: number` を追加。
いずれも既存の計算経路上にあり、追加コストはほぼゼロ。`serialize()` には含めない。

## 4. 感情モデル

### 4.1 内部表現は 3 軸

離散ムードを直接遷移させるとチカチカするため、まず連続 3 軸を更新し、そこから量子化する。

| 軸 | 範囲 | 主な寄与 |
|---|---|---|
| `valence`（快−不快） | -1..1 | `rewardTrend`、生存時間 vs 中央値 |
| `arousal`（緊張） | 0..1 | `valueDrop`、TD誤差の大きさ |
| `confidence`（確信） | 0..1 | `margin`、`1 - epsilon`、`1 - newStateRate` |

各軸は毎フレーム `x += (target - x) * 0.08 * dt60` で追従させる。

### 4.2 量子化するムード（7種）

| ムード | 条件（概略） | 観察者への意味 |
|---|---|---|
| `focused`（集中） | conf ≥ .6, arousal < .5, valence ≥ 0 | わかっている手を打っている |
| `thriving`（手応え） | valence ≥ .45, 生存 > 中央値×1.3 | 今回は明らかに調子がいい |
| `probing`（手探り） | newStateRate ≥ .25 or epsilon 高 | 初めての状況を試している |
| `confused`（混乱） | \|tdErrorAverage\| 急上昇, conf < .35 | 予想と現実がズレている |
| `pressured`（切迫） | arousal ≥ .7, valueDrop 大 | 見込みが下がり続けている |
| `stuck`（停滞） | `failureSignature` が直近5件中3件以上一致, valence ≤ 0 | 同じところで死に続けている |
| `reeling`（呆然） | エピソード失敗直後 3 秒 | 今のは効いた |

**チラつき防止**:
- 最低持続時間 6 秒（台詞の表示時間と揃える）
- 遷移にヒステリシス（進入閾値と離脱閾値を 0.1 ずらす）
- 優先度: `reeling` > `pressured` > `stuck` > `confused` > `probing` > `thriving` > `focused`

## 5. 話し言葉で出す

### 5.1 文体

書き言葉の実況ではなく、**AI が独り言をこぼしている**ように書く。

- 常体のくだけた話し言葉。「〜だ」「〜である」は使わない
- 言い淀み・省略・自問を許す（「あー」「え、」「……なんで？」）
- 完成した分析文にしない。**気分の断片**として出す
- 1〜2 行、全角 40 字以内

```text
probing    「ここ来たことないな。どっち行こう」
confused   「え、いま何が起きた？」
           「さっきと同じつもりだったんだけどな……」
stuck      「またここか。もう5回目だよ」
thriving   「あ、これいけるわ」
           「今日わりと見えてる」
pressured  「まずい、じりじり押されてる」
reeling    「……いま死んだ？」
focused    （沈黙）
```

### 5.2 表示時間と頻度

人間に読ませるための時間を確保する。

| 項目 | 値 |
|---|---|
| 表示時間 | 1行 = 5秒 / 2行 = 8秒（Quirk の台詞は 10秒） |
| フェード | 入り 0.3秒 / 出 0.6秒 |
| 台詞の最短間隔 | 表示終了から 4秒 |
| 同一カテゴリの再発話 | 25秒 |
| 1エピソードの上限 | 12件 |

**表示中に上書きしない。** 次の台詞は必ずキューに入れ、読み終わってから出す。
キューが 2 件を超えたら古い方を捨てる（渋滞させない）。

### 5.3 ムードリング（常時表示）

台詞と違い、これは切れ目なく出す。

- 機体まわりの細いリング、または HUD 隅の円
- 色相 = valence（赤〜青緑）、彩度 = confidence、脈動速度 = arousal
- 直近 30 秒の推移を細いスパークラインで併記

色だけに頼らないよう、脈動速度とスパークライン形状でも区別できるようにする。

## 6. Quirk（奇行）— たまに、台詞と同時に妙なことをする

**この体験の山場。台詞と行動が同時に出ることが要点で、片方だけでは成立しない。**

```text
        ┌─ 台詞    「ちょっと気になることがある」
同時 ───┤
        └─ 行動    敵を全部無視して、画面の隅へまっすぐ飛んでいく
```

観察者の反応が「**え、いま何した？**」になるのが正解。
だから**説明してから実行してはいけない**。台詞は理由をほのめかすだけで、明かさない。

### 6.1 頻度 — これが設計で一番重要

| 項目 | 値 |
|---|---|
| 発生間隔の目安 | **8〜15分に 1 回**（3〜5 エピソードに 1 回程度） |
| クールダウン | 最低 6 分。直前の Quirk 終了から数える |
| 同時発動 | 常に 1 つまで |
| 継続時間 | 4〜20 秒（種類による）。長引かせない |

条件が揃っても即発火させず、**確率的に間引く**（条件成立時に 15% で発火、など）。
毎回起きると「そういう仕様」になってしまい、不思議さが消える。
**予測できないことが、この機能の中身そのもの。**

### 6.2 奇行カタログ

台詞と行動は必ずセットで定義する。台詞は短く、含みを持たせる。

| 台詞（同時に表示） | 同時に起きる行動 | 継続 | 内部的な理由 |
|---|---|---|---|
| 「ちょっと気になることがある」 | 敵を無視して未踏の一角へ直行 | 12秒 | 訪問回数が極端に少ない状態へ誘導 |
| 「利き手じゃない方でやってみる」 | 最も多用している行動を封印 | 20秒 | `thriving` 継続。単調化の自壊 |
| 「……この形、前にも見た気がする」 | 数秒だけ完全停止して撃たない | 4秒 | 直近の `failureSignature` と一致 |
| 「もう一回だけ試させて」 | 直前に死んだのと同じ状況へ自分から突っ込む | 到達まで | `stuck` の穴を潰しに行く |
| 「今日はこれ抜きでいく」 | 特定の武器・行動を1つ使わない | 20秒 | 価値が過大評価されている疑い |
| 「なんか今日は違う気がするんだよな」 | 探索率を跳ね上げ、動きが荒くなる | 15秒 | `stuck` が長期継続 |

行動側は**見た目に明らかに逸脱している**必要がある。微妙な差では気づかれない。
奇行中はムードリングを紫にし、機体に薄いアウトラインを出して「今は普通じゃない」ことだけ示す。

### 6.3 「未踏の一角」をどう知るか（最小限の記録）

1 番目と 4 番目の奇行のために、`visitCounts: Map<string, number[]>`（状態 × 行動）を持つ。
`decide()` で +1 するだけで、常時これに基づいて動くことはしない。**発火時に参照するだけ。**

行き先は、状態キーを粗く畳んだ単位で選ぶ。

```ts
// 既定: 状態キーの先頭 3 フィールド
// （arena_shooter_core.ts:429 のように、全ゲームの encodeState は区切り文字で
//   離散フィールドを連結している）
bucketOf(key) = key.split(':').slice(0, 3).join(':')
```

訪問回数が最少で、かつ**過去に 1 回以上到達した実績がある**バケットを選ぶ。
一度も見たことのない場所は、行き方が分からないので選ばない。

弱点マップの常時表示や、内発報酬による恒常的な探索ドライブは**入れない**。
毎エピソード穴埋めに行く AI は、奇行ではなくただの仕様になる。

### 6.4 種明かしは後から

その場では説明しない。エピソード終了カードで初めて理由が出る。

```text
QUIRK: 「ちょっと気になることがある」
       → 未踏の一角へ 12秒。3 パターン新規に遭遇
```

**その瞬間は不思議で、後から腑に落ちる。** この時間差が観察の density を上げる。

### 6.5 安全弁

- Champion 評価中（`setEvaluationMode(true)`）は発火しない
- Q テーブルは触らない。変更するのはハイパーパラメータと一時的な行動マスクのみ
- 発火・解除・効果を必ずログに残し、成績変化を Quirk 由来と Skill 由来に分離できるようにする
- 内発報酬を使う場合も外部報酬とは別集計にし、終了カードと Champion 評価には混ぜない

### 6.6 効いた奇行を覚える

発火前 3 エピソードと発火後 3 エピソードの生存中央値を比較し、その奇行の価値を更新する
（6本腕のバンディット。`arena_shooter_agent.ts:131` の `updateUpgradeValue()` と同じ形）。

- 効いた奇行ほど選ばれやすくなる。セーブに含める
- 台詞に反映できる →「これ前もやったけど、やっぱダメだったな」

観察者から見ると、**AI が自分の奇癖の扱い方を覚えていく**。
長時間観察でしか見られないものになる。

### 6.7 人間からも撃てる

HUD にボタンを置き、手動発火もできるようにする。
提案書 2.2 の「必要なときだけ介入する管理者」に、具体的な操作が 1 つ増える。
手動発火もバンディットの学習対象に含める。

## 7. エピソード終了カード

提案書 3.2 の GAME OVER 表示に、気分と奇行を足す。

```text
EPISODE 42
SURVIVED 01:18   +12 sec vs previous
BEST 02:06
REWARD +184
LEARNED: avoided overload earlier
MOOD: 手探り → 集中
QUIRK: 「利き手じゃない方でやってみる」→ 主武器を20秒封印（効果 +9s）
REDEPLOYING IN 1.5s
```

Quirk 行は**起きたエピソードにだけ**出す。毎回出ると特別感が消える。

## 8. 実装計画

### Phase 0 — 信号の露出

1. `shared/rl/tabular_q_agent.ts` に `tdErrorAverage` / `newStateRate` / `lastTerminalStateKey` を追加
2. `TabularDecision` に `margin` を追加
3. ハイパーパラメータを可変にする（現状 `learningRate` は `readonly`。`setLearningRate()` を追加）
4. 一時的な行動マスク上書き `setActionVeto(indices, seconds)` を追加
5. `visitCounts` を追加し `serialize()` / `restore()` に含める（保存形式 version 2）。
   `qTable` と同じ LRU 追い出し（`maximumStates`）に必ず追従させる。片方だけ残すとキーがずれる
6. 既存呼び出し側（`apps/arena-shooter/arena_shooter_agent.ts`、`apps/gunship/gunship_rl.ts`）を追従

### Phase 1 — 共通モジュール

| ファイル | 役割 |
|---|---|
| `shared/rl/agent_mood.ts` | `MoodTracker`。3軸 + ムード + 台詞キュー |
| `shared/rl/agent_quirk.ts` | `QuirkDirector`。発火判定・間引き・適用・効果測定バンディット |
| `shared/rl/mood_phrases.ts` | 既定の話し言葉テーブル（アプリ側で上書き可） |
| `shared/mood_panel.ts` | リング / スパークライン / 吹き出しの DOM 描画 |

`MoodTracker` と `QuirkDirector` は Three.js にも DOM にも依存させない（headless テスト可能に）。

### Phase 2 — Arena Shooter へ適用して検証

奇行 6 種のうち、まず 3 種（未踏へ直行 / 主武器封印 / 完全停止）だけ入れて頻度を詰める。

### Phase 3 — 横展開

`gunship` → `one-line-rpg` → `zombie-survivor` → `network-defense`。
§3.3 のとおり、各ゲームでの追加実装は原則ゼロ（語彙の差し替えのみ任意）。

## 9. 受け入れ基準

| 項目 | 基準 |
|---|---|
| 無イベント時間 | 台詞もムード遷移も無い連続時間の中央値が 20 秒以下 |
| チラつき | ムード遷移が 10 秒あたり 1.5 回以下 |
| 可読性 | 台詞は表示時間中に上書きされない（キュー動作の単体テスト） |
| 静粛性 | 熟練フェーズ（生存 > 3分）で台詞が 1 分あたり 2 件以下 |
| **奇行の希少性** | **60 分の連続実行で Quirk 発火が 4〜8 回に収まる** |
| **同時性** | 台詞の表示開始と行動変化の開始が同一フレーム（単体テスト） |
| 根拠性 | 全台詞・全 Quirk にトリガー条件と数値スナップショットが紐づく |
| **非干渉** | Quirk を無効にすると、同一 seed の 50 エピソードの結果が Mood 有無で完全一致 |
| **追跡性** | 成績の変化を Quirk 由来と Skill 由来に事後分離できる |

「奇行の希少性」を数値基準に入れたのが要点。**多すぎたら失敗**という判定を明示する。

## 10. あえて入れないもの

- LLM による自由生成の台詞（レイテンシと、根拠のない発話のリスク）
- 気分がじわじわ行動に染み出す実装（原則 2.2。Quirk に集約する）
- 顔グラフィックや表情差分（コストに対して情報量が薄い。まずリング + 話し言葉で検証）
- ゲーム固有の危険度・死因定義（§3 のとおり共通信号で代替する）
- **恒常的な好奇心ドライブ（内発報酬・弱点マップの常時表示）** — 毎回やると奇行が仕様になる。
  未踏情報は Quirk 発火時に参照するだけに留める
- ニューラルネットによる好奇心（RND / ICM）。表形式 Q に対して訪問回数で十分足りる

なお、探索時の一様乱数を UCB に置き換える改善（`tabular_q_agent.ts:76`）は学習効率の話で、
観察体験の設計とは別軸。必要なら独立した変更として扱う。
