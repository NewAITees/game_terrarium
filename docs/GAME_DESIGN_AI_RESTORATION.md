# AI復興都市：人間操作・模倣学習・強化学習の設計

## 1. このゲームで起きること

滅びた都市を、目覚めたばかりの管理AIが復興する。

プレイヤーは都市を直接操作するのではなく、AIが古い制御盤を操作していく様子を観察する。AIは最初から賢いわけではなく、画面を見て、マウスを動かし、ボタンをクリックし、結果を確認しながら都市の動かし方を覚えていく。

人間も同じ制御盤を操作できる。人間の操作は、単なるデバッグ用入力ではなく、AIにとっての「先生の行動」として記録できる。

このゲームの中心は、次の循環である。

```text
人間が操作する
    ↓
AIが操作をまねる
    ↓
AIが自分で試行錯誤する
    ↓
AIの行動が変化する
    ↓
都市と物語が進む
```

## 2. 人間操作は別のゲームではない

人間操作、模倣学習、強化学習は、別々のゲームモードを作るという意味ではない。

すべてが同じゲーム画面、同じゲーム状態、同じ操作APIを使う。

| 操作者 | 操作の目的 | ゲーム内での意味 |
| --- | --- | --- |
| 人間 | 都市を動かす | AIに手本を見せる、または直接助ける |
| 模倣AI | 人間の操作を再現する | 古い制御盤の使い方を覚える |
| 強化学習AI | 報酬を最大化する | より効率的な都市運営を発見する |

したがって、人間が操作した結果はそのまま模倣学習用データになる。人間操作を後から別の形式に変換するのではなく、最初から「学習可能な操作ログ」として記録する。

## 3. プレイヤーが実際に行うこと

最初のプレイヤー体験は、難しい都市経営ではなく、壊れた制御盤を使ってAIを助けることである。

### 序盤

- 発電機のスイッチを探す
- マウスをボタンまで移動する
- ボタンをクリックする
- 蓄電池の残量が増えることを確認する
- 次に押すべきボタンをAIに教える

AIは最初、画面の意味を理解していない。ボタンを外したり、関係のない場所をクリックしたりする。人間が何度か操作すると、AIはその画面と操作の対応をまね始める。

### 中盤

都市には複数の施設が登場する。

- 発電所
- 採掘施設
- 修理工房
- 食料生産区画
- 通信設備
- 探索ドローン
- 居住区

人間は「発電を優先する」「故障前に修理する」「探索に電力を回す」といった方針を操作で示す。AIは人間の判断を学習した後、自分の経験から別の優先順位も試す。

### 終盤

AIは、人間が教えなかった状況にも遭遇する。

例えば、発電所を増やしすぎると部品が不足し、探索を優先しすぎると都市が停止する。ここでは人間のまねだけでは十分ではない。AIは、行動の結果に対する報酬を使って、長期的な計画を学ぶ。

## 4. 3つの学習段階

### 段階A：人間の操作を記録する

人間が制御盤を操作する。ゲームは次の情報を記録する。

- 操作前の画面またはゲーム状態
- マウスの座標と移動軌跡
- クリックした時刻
- 押したボタンや施設
- 操作後の資源量と施設状態
- 操作後に発生した結果

ログの例：

```json
{
  "observation": {
    "power": 42,
    "parts": 8,
    "generatorHealth": 0.31,
    "repairButtonVisible": true
  },
  "action": {
    "type": "move_and_click",
    "x": 814,
    "y": 226,
    "target": "repair_generator"
  },
  "result": {
    "generatorHealth": 0.51,
    "parts": 6
  }
}
```

### 段階B：模倣学習で人間の操作を再現する

AIには、次の問いに答えさせる。

> この画面、この都市状態、このマウス位置のとき、人間なら次に何をするか？

最初に学ぶ対象は、都市経営の最適解ではない。人間が行った操作の傾向である。

- どの施設を見るか
- どこへマウスを移動するか
- どのボタンをクリックするか
- どれくらい待つか
- 操作をどの程度ためらうか

この段階では、人間らしいマウス移動や、少し遠回りする操作も再現される。

### 段階C：強化学習で改善する

模倣したAIに、都市の結果に応じた報酬を与える。

短期報酬：

- 正しいボタンを押した
- 資源を獲得した
- 施設を修理した
- 生産量が増えた

長期報酬：

- 都市を長時間停止させなかった
- 資源の循環を維持した
- 新しい区画を解放した
- 探索によって重要な記録を発見した
- 復興方針に沿った都市を作った

模倣学習は「人間ならどう操作するか」を教え、強化学習は「この都市にとって何がよいか」を教える。

## 5. 操作APIは一つにする

人間、模倣AI、強化学習AIが同じゲームを操作できるように、入力経路を統一する。

```text
人間のマウス入力 ─┐
模倣AIの出力 ─────┼→ 共通Action → ゲーム状態更新
強化学習AIの出力 ─┘                         ↓
                                      観測・報酬・ログ
```

概念的な操作は次のようになる。

```ts
type Action =
  | { type: "move"; x: number; y: number }
  | { type: "click"; x: number; y: number }
  | { type: "wait"; duration: number }
  | { type: "select_facility"; id: string };
```

人間が実際のマウスを動かした場合も、AIが座標を出力した場合も、最終的には同じ `Action` に変換する。

これにより、次の機能を同じ仕組みで実装できる。

- 人間操作の記録
- 人間操作の再生
- AI操作の可視化
- AIと人間の操作比較
- 学習データの書き出し
- AIが迷ったときの人間介入

## 6. 人間とAIの関係

人間の役割は、単にAIを訓練する教師だけではない。3種類の関わり方がある。

### 教師として操作する

人間が制御盤を操作し、その行動をAIが学習する。

### AIを助ける

AIが迷ったときだけ、人間が操作を引き継ぐ。引き継いだ操作は、AIが苦手な状況の学習データになる。

### AIと競う

人間の都市とAIの都市を同じ条件で比較する。人間は探索を優先し、AIは生産を優先するなど、異なる復興方針が現れる。

## 7. 物語との接続

AIの学習履歴を、そのまま物語上の成長として扱う。

| システム上の変化 | 物語上の解釈 |
| --- | --- |
| クリックの失敗が減る | 制御盤の使い方を理解する |
| マウス移動が短くなる | 画面の構造を記憶する |
| 無駄な購入が減る | 資源の関係を理解する |
| 故障を予測する | 都市の未来を予測する |
| 人間の操作から外れる | 自分の判断を持ち始める |
| 人間と異なる方針を選ぶ | AI独自の文明観が生まれる |

AIが急に強くなるのではなく、画面の理解、操作の習熟、資源管理、長期計画の順に成長することで、学習の過程を観察できる。

## 8. MVPで実装する範囲

最初から本格的な強化学習を完成させる必要はない。最初の実験では、次の範囲に絞る。

1. 発電機、蓄電池、修理ボタンだけを持つ画面を作る
2. 人間がマウスで操作できるようにする
3. 操作ログを保存する
4. 保存したログを再生する
5. AIが「発電」「修理」「待機」を選べるようにする
6. 人間のログを使って簡単な模倣モデルを作る
7. 発電量と都市の安定時間を報酬にする
8. 模倣後のAIを強化学習で改善する

この時点で、次の問いに答えられる。

> 人間が操作したゲームを、AIがまねて動かし、その後に自分で改善できるか？

施設の増加、インフレーション、探索、物語分岐は、この循環が確認できた後に追加する。

## 9. この企画の要点

このゲームでは、人間操作は強化学習と別の要素ではない。

人間操作は、

- プレイヤーがAIを助ける方法
- AIにとっての教師データ
- AIが迷ったときの介入手段
- AIと人間の違いを見せる比較対象

を兼ねる。

最終的なゲーム体験は、都市の資源が増えることだけではない。

```text
人間が教える
    ↓
AIがまねる
    ↓
AIが失敗する
    ↓
AIが改善する
    ↓
AIが人間とは違う判断をする
```

その判断の変化を、都市の復興と物語の進行として画面上で観察する。

## 10. α版の30分プレイ構成

α版では、施設を増やすこと自体を目的にせず、「AIの自律範囲が広がる」ことを施設の復旧として見せる。

| 施設 | 役割 | プレイ上の意味 |
| --- | --- | --- |
| 発電区画 | 電力を作る | AIを動かすための最初の生命線 |
| 蓄電池 | 電力を貯める | 放置・突発故障への余裕 |
| 修理工房 | 故障を直す | AIが自分の稼働を維持できるようになる |
| 採掘場 | 部品を作る | 施設更新の資源源 |
| 温室区画 | 食料・生体資材を作る | 放置中の継続生産を解放する |
| 通信塔 | 旧文明の記録を探す | 物語と次の目標を解放する |
| ドローン庫 | 探索を自動化する | AIの視界を都市外へ広げる |
| 都市中枢 | 全施設を統合する | α版の到達点。AIが復興方針を自分で選び始める |

想定ペースは次の通り。

```text
00–05分  人間が発電・修理を教える
05–10分  AI補助が始まり、採掘と温室を復旧する
10–18分  AIが自分で電力を維持し、通信塔を起動する
18–25分  ドローン探索と施設更新を進める
25–30分  都市中枢が目覚め、AI独自の復興方針が見える
```

実際のα版では、最初の人間操作を教師データとしてブラウザ内の小型MLPに入力する。入力は電力、復興率、部品数、復旧済み施設など8個の状態値、出力は「発電・修理・採掘・通信探索・設備更新」の5行動とする。各人間操作の直後にオンラインSGDで更新するため、学習ボタンは存在しない。

このMLPは研究用の性能を狙ったものではなく、プレイヤーが「自分の操作でAIの判断が変わった」と感じるための可視化可能な学習器である。本格的な学習評価を行う段階では、保存した操作ログを使って別プロセスで訓練したモデルに置き換える。

## 11. α版で使用する素材

画面のSF UIには、OpenGameArtの[「Sci-fi User Interface」](https://opengameart.org/content/sci-fi-user-interface)にあるCC0素材を参考にする。ロボットには同サイトの[「Pixel Robot」](https://opengameart.org/content/pixel-robot)のCC0素材を使用する。

CC0素材は、作者表示なしで利用できるが、α版では出典を残す。Cookie Clicker本家の画像・名称・UIは使用しない。
