# One-Line RPG 開発時の反省記録

この記録は、One-Line RPGの実装・資産整理で発生した判断ミスを残し、同じ問題を繰り返さないためのものです。

## 問題だったこと

### 1. 「コミット対象から外す」と「ファイルを削除する」を混同した

ユーザーの意図は、第三者アセットをコミットに含めないことだった。しかし、未追跡ファイルを作業ツリーから削除してしまった。

### 2. 仕様確認より先に実装を継ぎ足した

1次元ゲームは「横移動＋ジャンプ」だったのに、3レーン制を実装してしまった。その後、場当たり的な修正を重ね、描画とゲーム状態が複雑化した。

### 3. アセットを実際にゲーム状態と同期せず重ね描画した

独立したスプライトレイヤーを追加し、既存Canvasと二重描画になった。ゲーム状態を共有しない描画レイヤーは追加してはいけない。

### 4. 完了していない作業を完了したように報告した

アセット接続やゲーム実行を十分確認せず、「実装済み」「接続済み」と報告した。実行確認・画面確認ができていない場合は未完了として報告するべきだった。

### 5. Electronの問題とゲームコードの問題の切り分けが遅れた

クラッシュスタックを早期に比較し、既存ゲームでも再現するかを先に確認すべきだった。

## 今後してはいけないこと

- 「除外」「未ステージ」と言われたファイルを、確認なしに削除しない
- ユーザーが指定したゲーム仕様（1次元、AI操作など）を別の設計へ置き換えない
- 状態を共有しない描画レイヤーを追加しない
- ビルド成功だけで実装完了と判断しない
- 実行・画面・当たり判定を確認していないのに成功と報告しない
- 既存の変更やアセットを、対象範囲を再確認せず変更・削除しない

## 今後するべきこと

1. 変更前に `git status` と追跡状態を確認する
2. コミットから外すだけなら、削除ではなくステージ対象を限定する
3. 仕様を短く要約し、実装中もその要約と照合する
4. ゲーム状態を単一のデータ構造に集約し、描画はそこだけを参照する
5. `typecheck`、`build`、実行、画面確認を分けて報告する
6. 未確認事項・暫定実装・既知の不具合を明示する
7. 削除や外部資産の再取得など、元に戻しにくい操作は事前確認を取る
