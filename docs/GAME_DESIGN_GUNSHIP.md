## コンセプト一行

**常に落下し続ける戦闘機を、RLエージェントが「機首の向いた方向にしか推力を出せない」
制約の下で浮かせ続けながら、下方の敵戦艦と空中の敵を撃つ。
「高度を保つ」と「狙って撃つ」が原理的に両立しない緊張を観察する、
2D横視点の重力シューティング。**

RL Arena が全方位・無重力の殲滅戦だったのに対し、本作は**縦軸（高度）を最大の
戦術リソース**に据える。落下は撃墜と同義であり、攻撃はその貯金を切り崩す行為になる。
RLエージェントが学ぶのは照準精度だけではなく、「いつ機首を下げて撃ち、いつ上げて
高度を取り戻すか」という時間配分そのものである。

---

## ゲームの4本柱

1. **重力が生む攻守の分離**
   上を向けば生き延びられるが撃てない。下を向けば撃てるが落ちる。攻撃と生存が
   同じ「機首方向」という一本の軸を奪い合う。ここが本作の全て。
2. **観察して分かる操縦の上達**
   命中率だけでなく、最低高度マージン・下向き姿勢の滞在時間・落下死率を可視化し、
   「大胆に撃てるようになった」「落ちなくなった」を画面の動きとして読ませる。
3. **敗北は訓練結果**
   撃墜（落下・被弾）はゲームオーバーではなくエピソード終了。報酬・戦闘ログ・
   モデル更新・恒久資源を確定し、数秒後に次の出撃へ入る。
4. **邪魔しない常駐ゲーム**
   大画面での観察でも画面隅での放置でも成立する。人間の介入は恒久研究・報酬設計・
   ラン中3秒のレベルアップ選択に集中させ、通常操縦はRLが担う。

## 目標としないもの

- プレイヤーの反射神経を主役にする手動フライトシューター
- 敵HPと自機DPSだけを指数的に増やす放置ゲーム
- 学習しているように見せるだけの固定スクリプト飛行
- セーブ更新で過去の学習成果を失う構造
- 重力を「たまに落ちる演出」に留め、攻守分離のジレンマを骨抜きにすること
- 手動操作・マウス照準・ドッジ連打など、人間の腕前を前提にした操作系

**操縦は一貫してRLエージェントが担う。** 人間向けの操作系・アクセシビリティ
（オート射撃、速度調整、進行保証など）は設けない。参考2作の「手動操作の楽しさ」は
本作の対象外で、RLの学習と観察に置き換える。物理チューニングの確認は、手動プレイ
ではなく数値ログとスクリプト化テストパイロットで行う。

## ベース（RL Arena）との関係

`apps/arena-shooter/` とは**独立した新アプリ**として実装する。理由は、重力物理・
上下非対称の地形・高度リソースという中核が既存の全方位無重力設計と大きく異なり、
コードも設計も分離した方がクリーンなため。

共有するのは思想と基盤のみ：

| 共有する | 分離する |
|---|---|
| 観察型シリーズの演出哲学（宇宙ドキュメンタリー的リアリズム） | 移動・照準の物理モデル |
| RL基盤（観測ベクトル→方策→行動、モデル世代管理、Ascension） | ワールド構造（横視点・海面境界・空域） |
| WAVE制無限進行 / 撃墜→学習確定→自動再出撃 | 敵アーキタイプ（戦艦・対空・空中機動） |
| セーブ設計・巨大数・オフライン進行の枠組み | アップグレードツリー |
| レベルアップの高レベル方策としての扱い | 報酬設計（高度項が中心に加わる） |

RL基盤の共通化できる部分は `shared/` に切り出すことを検討する。

## 参考作品：LUFTRAUSERS / Jet Lancer

本作の物理ジレンマは、既に商業作品で成立が実証されている。設計は**この2作の
物理を土台に、操縦者を人間からRLに置き換え、放置観察に作り替える**もの。

### LUFTRAUSERS（Vlambeer / Devolver, 2014）— 物理の直接の祖

- **操縦**：「推力＝機首方向」「左右で旋回」「下で減速」。**360度動けるが射撃は前方のみ。**
  → 本作の「推力＝機首＝砲が一体」は完全に同型。
- **推力を入れると旋回速度が激減する。** 素早く狙うにはエンジンを切る＝落下を受け入れる。
  → 本作の物理に **「推力ON中は `turnRate` を下げる」を採用**（下記メカニクスに反映）。
- **エンジンを切ると予測可能な放物線で海へ落ち、その落下を使って180度反転し、
  追う敵に照準を合わせる。** ＝本作の CLIMB→照準→BURST→RECOVER の実在原型。
  「落下は敗北でなく機動リソース」という核が既に証明済み。
- **HP＝機体を囲む円。被弾で縮み、射撃していない時だけ回復。** 「撃つ／生存」の
  トレードオフ。→ 本作に**任意採用**（「撃つ／落ちない」と二重の緊張になる）。
- **敵は戦闘機・戦艦・潜水艦。** → 本作の敵設定と一致。**潜水艦を敵候補に追加**（下記）。

### Jet Lancer（Code Wakka / Armor Games, 2020）— 現代的拡張

- 重力ベース物理は LUFTRAUSERS への負債を自認。非推進時も慣性・緩降下、移動は前方のみ。
- 追加要素：**ドッジ**、チャージ特殊攻撃。→ 本作アップグレードの**ドッジ/回避能力**の参考。
  （Jet Lancer のマウス照準・手動操作系は**本作では採用しない** — 操縦はRLが担うため。）
- **ボス戦（巨大ロボ）が最大の見どころ。** → 本作 Boss（Dreadnought）の重視方針を裏付け。
- 空母ハブで機体パーツ強化・ロードアウト → 本作の恒久研究UIの参考。

### 本作が2作から離れる点（＝独自性）

| 軸 | LUFTRAUSERS / Jet Lancer | 本作 |
|---|---|---|
| 操縦者 | 人間（高スキルキャップの手動操作が主役） | **RLエージェント**（人間は観察・研究） |
| 目的 | スコアアタック / ミッション攻略 | **AIの操縦上達の観察** と無限進行 |
| 時間構造 | ラン/ミッション単位 | **無限Wave・放置観察・撃墜＝学習確定** |
| 上達の主体 | プレイヤーの反射神経 | **モデル世代の学習**（臆病→大胆の変化を見る） |
| 敗北 | リトライ | エピソード終了→報酬確定→自動再出撃 |

> 一言で表すと、
> **「LUFTRAUSERS の物理を、人間ではなく強化学習エージェントが何時間もかけて
> 上達していく様子を眺める箱庭。」**

### ビジュアル面の教訓

両作とも**2D空戦の視認性のため背景を疎に**している（Jet Lancer 評でも「背景は所々
あっさり」）。本作は「見た目重視」だが、これは**リッチさより可読性が優先**という
制約でもある。パララックスや海面演出で雰囲気を出しつつ、戦場中央（機体・弾・敵）の
コントラストと視認性を最優先する（アート方針の柱と一致）。

## コアメカニクス：推力＝機首一体型物理

**本作を定義する唯一にして最重要のルール。**

### 物理モデル（ルナランダー型）

- 機体には毎tick **一定の重力加速度 `g`（下向き）** がかかる。
- 推力は**機首が向いている方向にのみ**発生する（推力ベクトル＝機首方向）。
  横向きにも下向きにも「浮上専用エンジン」は存在しない。
- 速度はニュートン物理で積分され、慣性が残る。急停止・急旋回はできない。
- 機首方向は角速度で回頭する（`hullTurn`）。回頭にも時間がかかる。
- 主砲は**機首方向に発射**する（固定前方砲）。＝狙う方向と推力方向が完全一致。

この一体化により、次が原理的に成立する：

> **下の戦艦を狙う＝機首を下に向ける＝推力が下を向く＝重力と合わさって急降下する。**
> **上を向いて浮上している間は、下の戦艦を撃てない。**

### 運動方程式（実装の基準）

毎tick `dt` で以下を積分する。`θ` は機首角（0=右水平、+で上向き、-で下向き）。

```text
推力ベクトル:  F = thrustOn ? thrustMax * (cosθ, sinθ) : (0, 0)
加速度:        a = F/m + (0, -g) - drag * v
速度:          v += a * dt
位置:          p += v * dt
機首角:        θ += hullTurn * turnRate(thrustOn) * dt   （hullTurn ∈ {-1,0,+1}）
```

- **`turnRate` は推力ONで低下させる（LUFTRAUSERS 由来）**：`turnRate(on) = turnRateBase * k`,
  `k ≈ 0.4〜0.6`。＝素早く機首を振って狙うには推力を切る＝落下を受け入れる、という
  もう一段の攻守トレードオフが生まれる。「推力を切って自由落下しながら180度反転し、
  下や後方の敵に照準を合わせて撃つ」という高等機動がここから創発する。
- `drag`（空気抵抗）を薄く入れると速度が発散せず、機体が「重い航空機」らしく
  振る舞う。ゼロにすると宇宙的な滑りになり本作の手触りから外れる。
- **`thrustMax/m` と `g` の比＝Thrust-to-Weight比 (TWR)** が全チューニングの支点。
  - TWR < 1：機首を真上に向けても浮上できない（常に負けの機体、不採用）。
  - TWR 1.3〜1.8：浮上はできるが余裕が薄い。ジレンマが鋭く、観察が面白い推奨帯。
  - TWR > 2.5：ほぼ自由飛行になり重力ジレンマが骨抜き。上げすぎない。

### 高度という貯金 ＝ バースト＆リカバリー

高度は「貯めて消費するリソース」。基本の交戦サイクルは4フェーズ：

1. **CLIMB（貯金）**：機首を上げて推力ON。安全高度と上向き速度を確保する。
2. **NOSE-DOWN（照準）**：機首を下へ回頭。この間は推力も下向きになるので落下が始まる。
3. **BURST（放出）**：戦艦に狙いが乗った一瞬で射撃。落下速度が乗るほど残り猶予が減る。
4. **RECOVER（回収）**：機首を上げ直し推力で減速・再上昇。海面に呑まれる前に立て直す。

RLが習得すべきは「**現在の高度マージンから逆算して、フェーズ2〜3に何フレーム
費やしてよいか**」。浅い機体は臆病に短く撃ち、熟達すると海面ギリギリまで粘って
一度の降下で複数の戦艦を薙ぐ——この差が観察の見どころになる。

### 落下境界と二重リスク

- 画面下部の**海面が絶対の落下境界**。機体が海面に触れたらエピソード終了（落下死）。
- 海面付近には敵戦艦がいるため「深く降りて撃つ」ほど戦艦の対空砲射程に入る。
  高度を下げるリスクが**二重（落下＋被弾）**になる。
- （任意の深み）**海面効果**：海面近くでは推力効率が僅かに落ちる／波飛沫の視覚ノイズで
  照準が読みにくくなる、などのペナルティを足すと「降りすぎ」の危険が体感で伝わる。

### 補助パラメータ（チューニング用）

- `g`：重力加速度。大きいほどジレンマが鋭い。
- `thrustMax` / `m`：TWR を決める最重要ペア（上記）。
- `turnRate`：回頭速度。遅いほど「下を向いてから戻る」コストが上がる＝ジレンマ深化。
- `drag`：速度の収束と機体の重さ。
- `fuel`（任意）：初期は無燃料（推力自由）で物理ジレンマだけに集中し、後で燃費を
  アップグレード軸／報酬項として追加する案。

## 環境レイアウト

2D横視点・固定画面（RL Arena 同様、レスポンシブ表示で縦横比に依存しない観測）。

```
上端 ─────────────────────────────  （天井：任意でソフト境界）
        ✈ 自機（生存圏）
   空中の敵（機動・脅威が近い） ◆   ◆
        ・
        ・      ← 高度マージン（貯金）
        ・
   ▲対空砲弾   ▲対空砲弾
海面 ══════════════════════════════  （落下境界＝撃墜）
   🚢 敵戦艦   🚢 敵戦艦（高耐久・遠い脅威・対空砲）
```

- **下部：海面**＝落下境界。その上に敵戦艦（高耐久・低速・対空弾で反撃）。
- **中〜上部：空域**＝機体の生存圏。空中の敵機（機動・接近が速い・脅威が近い）。
- **標的の非対称性**が戦術の核：
  - 戦艦は**遠い脅威**だが、倒すには高度を捨てて降りる必要がある（落下リスク）。
  - 空中機は**近い脅威**で、放置すると被弾するが、同高度なので撃つのに落下しない。
  - → RLは「まず空中機を捌いて安全高度を確保 → 余裕を作って戦艦を叩く」という
    優先順位を学ぶことが期待される。

## コアループ

### 人間が行うこと

- 出撃前：機体アーキタイプ・武器・報酬プリセット・学習方針を選ぶ。
- ラン中：レベルアップ時の3択に**3秒だけ**介入できる（未選択ならRLが選ぶ）。
- ラン後：恒久研究、報酬設計の調整、モデル世代の昇格判断。
- 基本は**眺めるだけ**で進行する。

### RLエージェントが行うこと（毎tick）

1. 観測ベクトルを受け取る（下記「RL設計」）。
2. 機首回頭・推力ON/OFF・射撃・標的選択・武器選択を出力する。
3. 高度マージンと脅威から「今下を向いてよいか」を判断する。
4. 撃墜されたらエピソードを終了し、報酬を確定してモデルを更新、自動再出撃。

### エピソード終了条件

- 落下死（海面接触）
- 被弾によるHP0
- （任意）燃料切れによる制御不能落下

## RL設計

RL Arena の枠組み（Stage A: Tabular Q → Stage B: DQN → Stage C: 階層方策）を継承する。
本作固有なのは**高度・重力・機首方向を中心に据えた観測と報酬**。

### 観測（構造化ベクトル）

```text
自機:
  高度（海面までの距離）, 上端までの距離, 縦速度, 横速度, 速度ベクトルの向き,
  機首方向, 回頭中の角速度, 現在の推力ON/OFF,
  「現高度から機首を真下にして撃ったとき海面到達までの推定余裕フレーム数」,
  各武器CD, HP

高度センサー（本作の核）:
  最低安全高度マージン（今すぐ機首を上げても止まりきれるか）,
  下向き交戦可能フレーム数の推定,
  戦艦群の対空砲射程に入っているか

方向センサー（8〜12セクター, 機体中心の等角度）:
  最寄り敵距離, 敵密度, 敵弾距離, 接近速度, 推定被弾時間
  （空中機チャネルと戦艦チャネルと敵弾チャネルを分離）

優先候補上位N体:
  相対位置, 速度, HP, 種別（戦艦/対空/空中機/弾）, 脅威値

グローバル:
  Wave, 敵数帯, 敵弾数帯, 残敵, Boss状態,
  利用可能能力, 取得済み強化, 提示中の強化候補
```

生Canvas画像は使わない。学習速度・デバッグ性・決定再現性を優先し構造化ベクトルを使う。
**高度と縦速度は最重要チャネル**なので、方向センサーに埋もれさせず独立軸で観測する。
「海面到達までの推定余裕フレーム」を明示的に観測に入れることで、
危険度の内部推定を方策に押し付けず、落下管理の学習を助ける。

### 行動空間（Multi-Discrete）

```text
hullTurn:  -1 / 0 / +1     （機首回頭。左回り/なし/右回り）
thrust:    off / on        （推力。機首方向にのみ発生）
fire:      off / on        （主砲。機首方向へ発射）
target:    nearest / threat（空中機優先）/ ship（戦艦優先）/ weak / manual
weapon:    keep / next / slot 1..4
ability:   none / slot 1..2
```

- 全組み合わせを一つの巨大離散にしない。各ヘッドを分離するか階層方策で無効行動を
  マスクする。
- **`thrust` と `hullTurn` と `fire` の相互作用が学習の主戦場**。推力ONのまま機首を
  下げれば急降下しながら撃つ、推力OFFで自由落下しながら機首だけ回す、など多彩な戦術が
  この3ヘッドの組み合わせから創発する。
- レベルアップ選択は通常tickと別の高レベル方策として扱う（RL Arena と同様）。

### 報酬設計

```text
+ 撃破価値（戦艦は高配点・空中機は中配点）
+ 与ダメージ × 小係数
+ 生存時間 × ごく小さい係数
+ 危険弾/対空弾の回避成功
+ 高度マージンを保ったままの撃破（攻守両立ボーナス, 小）

- 被ダメージ
- 死亡（被弾）
- 落下死（明確な大きい負報酬）
- 危険高度（海面接近）での長時間滞在
- 無効射撃 / 過剰弾薬消費
- 同一行動の不必要な反復（推力ONずっと天井張り付き等）
```

**報酬ハックの警戒点（本作固有）：**

- 「天井付近でずっと浮いて撃たない」＝安全だが戦艦を無視する消極戦法。
  → 生存だけの報酬を極小にし、撃破と Wave 進行で稼がせる。天井付近の長時間滞在に
    小さな負報酬。
- 「高度を過剰に安全側に取り、決して降りない」＝戦艦を永遠に倒さない。
  → Wave をクリアするには戦艦撃破が必要な構成にし、進行報酬で降下を促す。
- 照準方向そのものへ強く報酬を与えすぎない。最終的には撃破と生存から
  「いつ降りて撃つか」を学ばせる。
- 海面接近時は上昇（機首を上げる）行動へ小さな正、さらに降下する行動へ小さな負、
  実際の落下死に明確な大負。落下を観測するだけでなく回避を学ぶ理由を作る。

### RLの成長を見せる指標（本作固有を太字）

- 10エピソード移動平均生存時間
- 同一装備・同一シードでの最高 Wave
- 命中率（**対戦艦 / 対空機を分けて**）、被弾/分、撃破/分
- **最低高度マージンの分布と、落下死によるエピソード終了率**
- **下向き（機首が水平より下）姿勢の平均滞在フレーム** … 大胆さの指標
- **バースト＆リカバリーの平均サイクル長** … 操縦リズムの洗練
- 推力ON率と燃費（無駄な推力の削減）
- 旧チャンピオンモデルとの評価戦勝率

モデル昇格は通常ランの一度の高得点ではなく、固定評価シード群で判定する。

## レベルデザイン / Wave

RL Arena の「Wave に終点はない」「敵解放帯（上限でなく解放）」「Director による
動的難度」「敵予算」の枠組みを踏襲する。本作固有の Wave 進行の狙い：

### 敵解放帯（例）

- **Calibration（初回 1〜5）**：空中機のみ・低速。基本の浮上と水平射撃を学ぶ。
- **Descent（初回 6〜15）**：初めて戦艦が出現。「降りて撃って上がる」を要求。
  戦艦は対空砲を持たず、まず降下の物理だけを学習させる。
- **Crossfire（初回 16〜30）**：戦艦が対空弾を撃つ。降下＝二重リスク。空中機と
  戦艦の**同時脅威**で優先順位判断を要求。
- **Siege（初回 31〜50）**：戦艦複数＋機動空中機の飽和。高度管理と標的配分の総合力。
- **Evolution（51以降・永久生成）**：Director がモデルの得意戦法を分析し、
  「天井に籠るモデル」には接近する高高度空中機を、「深く降りるモデル」には
  対空弾幕の厚い戦艦を、といった弱点を突く編成を生成する。

### Wave 進行の設計原則

- Wave クリア条件に**戦艦撃破を含める帯**を用意し、「降りない戦法」を無効化する。
- 難度は単調増加でなく波打たせる（強化直後にパワー誇示 Wave＝弱編成で殲滅の爽快感）。

## 機体アーキタイプ（機種）

### 機種の定義：「見た目」ではなく「物理定数のセット」

本作は**RLエージェントが操縦し、人間はそれを観察する**。したがって機種の意味は
プレイヤーの好みではなく、**エージェントが解くべき物理問題そのものを差し替える
ダイヤル**である。コアメカニクスの4定数がそのまま機種の正体になる。

| 定数 | 機種差として何を意味するか | 観察者に見える"性格" |
|---|---|---|
| **TWR**（`thrustMax/m` ÷ `g`, 1.3〜1.8） | ジレンマの強さそのもの。低TWR機は落下境界に近づくと戻れず高度管理がシビア | 「ギリギリで生きてる」緊張感 |
| **turnRate + k**（推力ON時の旋回低下係数） | 照準の付けやすさ。低旋回機はBURSTの一撃に賭け、高旋回機は小刻みに刺す | 攻撃リズムの粗さ／細かさ |
| **thrustMax / m** | 加速の鋭さ。重い機は慣性で流れ、軽い機はキビキビ止まる | 動きの"重量感" |
| **drag** | 速度の伸びと減衰。低dragは弾道が伸びるが止まれない | 高速一撃離脱か、粘る空戦か |

**機種＝planet_strategy の AI faction に相当する「性格の器」。** 同じ「戦艦を下向き
攻撃で沈める」問題を別の物理法則で解かせると、RLは**まったく違う戦い方に収束する**。
その差を眺めることが本作最大の見どころになる（観察型シリーズの肝＝AIの性格差が
見えること）。

### 設計原則：機種は「トレードオフ上の別の点」であり上位互換にしない

単に「速い・強い」機を上位互換として並べると観察の面白みが消える。**各機種は TWR と
旋回のトレードオフ上の別の座標**であるべき：速い機は落ちやすく、旋回が鋭い機は最高速が
出ない。どの機種にも「RLが必ずぶつかる固有の壁」があるのが理想。

### 具体パターン（4機種の例）と期待する挙動

| 機種 | TWR | 旋回(k) | drag | 物理的キャラクター | RLに収束してほしい戦法 | 観察の見どころ／固有の壁 |
|---|---|---|---|---|---|---|
| **Interceptor（軽量万能）** | 1.6 | 速い(0.6) | 中 | 加速も旋回も素直。ジレンマが最も穏やか | 小刻みなNOSE-DOWNで空中機を捌きつつ、こまめに降りて戦艦を削る | 基準機。学習が最も速く回り、他機種の挙動を測る物差し |
| **Hauler（重量ガンシップ）** | 1.35 | 遅い(0.4) | 高 | 重く慣性が強い。低TWRで落下からの復帰が苦しい | 高い安全高度を貯め、一度の深い降下で**複数戦艦をまとめて薙ぐ**バースト特化 | 「いつ降り始めるか」の判断ミスが即落下死。臆病→大胆の変化が最も劇的に出る |
| **Darter（高速一撃離脱）** | 1.8 | 中(0.5) | 低(伸びる) | 加速鋭く弾道が伸びるが止まれない。オーバーシュートしやすい | 高速で戦艦上空を通過しながら擦れ違いざまに撃つ、慣性を活かした弧の描き方 | 「止まれない」を制御に変えられるか。低dragゆえ海面へのオーバーラン落下が固有リスク |
| **Hoverer（低推力精密）** | 1.3 | 速い(0.65) | 高 | ほぼ浮けないTWRだが旋回だけは速い。最も落ちやすい | 海面から離れた中高度に居座り、機首だけ細かく振って精密射撃。降下は最小限 | TWRが1.3しかないため「籠り戦法」に流れやすい → 報酬設計（天井滞在の負報酬）との綱引きが観察できる |

**期待する観察体験**：同じ Wave・同じシードを4機種に解かせると、Hauler は「高く貯めて
一気に薙ぐ」、Darter は「駆け抜けながら擦る」、Hoverer は「なるべく降りずに精密に」、
Interceptor は「バランスよく捌く」という、**物理定数だけから創発する4つの異なる操縦
リズム**が見えるはず。学習初期は全機種が臆病に天井付近へ籠り、世代が進むと各機種の
物理に最適化された固有の"個性"が立ち上がっていく——この分岐こそが本作の主役の絵になる。

### 機種の選択と切替

機種は出撃前に決める。人間の関与は「どの物理問題をRLに解かせて眺めるか」の選択に
集約され、選び方は2パターンを用意する：

- **ランダム選択（おまかせ観察）**：機種を無作為に1つ選んで出撃する。放置・常駐観察の
  デフォルト。「今日はどの機体でAIがどう化けるか」を運任せで眺める箱庭的な遊び方。
  各機種の観測指標を横断で溜めれば、機種ごとの学習曲線の比較データにもなる。
- **機種指定（狙って観察）**：Interceptor / Hauler / Darter / Hoverer から明示的に1つ選ぶ。
  「Hauler が深い降下を習得する過程を見たい」など、特定の物理問題に絞って観察したいとき。

**機種を入れ替えたらゲームをリセットする。** 機種は物理定数のセットそのものであり、
Wave 進行・ラン内成長（XP強化）・その機体で学習中のモデル状態は現在の物理を前提に
積み上がっている。途中で物理を差し替えると学習も進行も意味を失うため、切替は
**現在のエピソード／ランを終了し、Wave を初期化して新しい機種で仕切り直す**。

- リセットの範囲：Wave カウンタ・ラン内XP強化・現在エピソードの状態を初期化。
- **保持するもの**：恒久研究、報酬プリセット、そして**各機種ごとに紐づく学習モデル
  世代**（機種Aで育てたモデルは機種Aに残る。機種Bへ切り替えても機種Aの学習は失われない）。
  → 機種は「別々に育つ4体のパイロット」として扱い、切替は担当機の載せ替えに近い。
- 切替UIは事故防止のため確認を挟む（放置観察中の誤操作でランを飛ばさない）。ランダム
  選択も「次の出撃から適用」とし、進行中のランを即座に破棄しない。

### 機種と検証

機種が正しく設計できているかは、「4機種の**下向き滞在時間・最低高度マージン・
バースト＆リカバリーのサイクル長**（観察指標）が、学習収束後に**互いに有意に異なる
分布**になるか」で判定する。全機種が同じ挙動に収束するなら、それは機種差が物理として
効いていない＝ダイヤルの設計不良のサインである。

## 武器・成長

### 武器の性質

主砲は機首方向固定のため、武器差は「一度下を向く時間でどれだけ稼げるか」に効く：

- **単発高威力**：短い下向き時間で戦艦に大ダメージ（低リスク型）。
- **連射**：下向き時間が長いほど有利だが落下リスク増（ハイリスク型）。
- **貫通/爆発**：戦艦と対空砲をまとめて処理し降下回数を減らす。
- **誘導/散弾**：空中機の処理を楽にして安全高度確保に寄与。

### ラン内成長（XP → 3択）

- 推力効率 / 回頭速度 / （燃料採用時は）燃費
- 砲の連射・射程・貫通・弾数
- 一時的な「浮上ブースト」能力（下向き中でも短時間だけ浮力を得る＝ジレンマの緩和枠）

### 恒久成長

- 機体研究（`thrustMax`・`turnRate`・HP 等の基礎値）
- 報酬プリセット、モデル世代（Training / Champion）比較
- Ascension（学習は保持したまま新環境へ再適応）
- オフライン進行

## アート・ビジュアル方針

**見た目は本作の主目的の一部。** 観察型シリーズである以上、「今この機体が攻めて
いるのか高度を立て直しているのか」が**言葉やゲージ以前に、絵として一目で伝わる**
ことが最優先。物理状態がそのまま画になるよう設計する。

### アートの柱

1. **姿勢と高度が絵で読める**：機首の角度・推力炎の長さ・海面との距離だけで、
   機体が攻撃中か回復中か危機かが分かる。HUDは補助であって主役ではない。
2. **空と海の縦のコントラスト**：上＝明るく開けた生存圏、下＝暗く重い危険域。
   高度を下げるほど画面が視覚的に「重く」なり、リスクが色で伝わる。
3. **ドキュメンタリー的リアリズム（シリーズ継承）**：フローティングスコア・過剰な
   フラッシュ・キラキラは使わない。爆炎・水柱・機体の傾き・弾道そのもので語る。
4. **1機の主役性**：大群を薙ぐ RL Arena と違い、本作は基本1機。機体は大きめ・
   丁寧に描き、姿勢アニメーションに情報量を持たせる。

### 画面の層構成（パララックス）

奥から手前へ、スクロール速度を変えた多層で「高さと空気感」を作る：

```text
Layer 0  空グラデーション（上=晴天ブルー / 下=水平線際のヘイズ）  … 固定
Layer 1  遠雲・太陽/月・鳥影                                    … 極ゆっくり
Layer 2  遠景の艦隊シルエット・水平線                            … ゆっくり
Layer 3  【海面】波・うねり・泡・反射のきらめき                   … 中速・境界の主役
Layer 4  【戦艦】艦体・砲塔・被弾煙                              … ゲーム速度
Layer 5  【自機・敵機・弾・爆発・推力炎】                         … ゲーム速度（最前面）
Layer 6  前景の水飛沫・薄雲（自機が横切る）・ビネット             … 速い/オーバーレイ
```

海面(Layer 3)は本作の生命線。**波の上下animと反射の明滅**で「落ちたら終わる境界」
の緊張を常に画面に出す。高度が下がると海面が画面を占め、色温度が下がる。

### 物理を絵に翻訳する（最重要）

| 物理状態 | 視覚表現 |
|---|---|
| 推力ON | 機首後方に**推力炎**。推力＝機首方向なので炎の向きで推力方向が読める |
| 推力の強さ | 炎の長さ・明度・揺らぎ量で表現（弱→短く赤、強→長く白青） |
| 機首角 θ | 機体スプライトの回転そのもの。攻撃姿勢＝機首が下、回復＝機首が上 |
| 落下中（推力OFF/下向き） | 炎が消える or 下向きの炎＋機体が海面へ吸われる構図＋速度線 |
| 高度マージン低下 | 画面下からせり上がる**危険ビネット**（赤み）。海面接近で振動を僅かに増やす |
| 被弾 | 機体の一瞬の白フラッシュ＋黒煙のトレイル（HP低下で煙が濃く常時化） |
| バースト射撃 | 短くシャープなマズルフラッシュと薬莢/反動。連射ほど機体が僅かに後ろへ煽られる |
| 戦艦撃破 | 大きな水柱・二次爆発・沈む艦体。派手だが「現実の重量感」を保つ |

「今どのフェーズか（CLIMB/照準/BURST/RECOVER）」を、色やアイコンでなく
**機体の向きと炎と高度**という物理の直接描画から読めるのが理想。

### 色・ムードのトーン

- 空：上部 `#6fb7e8` 系のクリアブルー → 水平線際は白っぽいヘイズ。
- 海：`#1c3a4f`〜`#0e2230` の深い青。時間帯プリセット（昼／夕／夜／嵐）で気分替え。
- 自機：識別性の高い暖色アクセント（機首や炎）で、暗い海面を背景にしても見失わない。
- 敵：戦艦＝無彩色の鋼＋赤いマーキング、空中機＝寒色で自機と弁別。
- 全体に**フローティング数字を置かない**。ダメージや報酬は絵とHUD端のメーターへ。

### スプライト／アニメーション要件（エンティティ別）

各エンティティに最低限用意したい状態：

- **自機**：機体ベース（角度は回転で表現）／推力炎（3段階の強度）／被弾フラッシュ／
  黒煙トレイル（HP段階）／撃墜（分解＋落下）。
- **戦艦**：艦体（大）／砲塔（独立回転して自機を狙う）／対空マズル／被弾煙（累積）／
  撃沈（傾斜→水柱→沈没）。
- **空中機（Chaser/Gunner/Diver）**：飛行ループ／射撃／被弾／撃墜。寒色で色替え版。
- **弾**：自機弾（暖色トレーサー）／対空弾（上向き曳光）／敵機弾。軌跡が読める曳光弾。
- **エフェクト**：爆発・水柱・マズル・推力炎・水飛沫・波きらめき。
- **背景**：空グラデ、雲、遠景艦隊シルエット、海面タイル（アニメ波）、前景飛沫。

### アセット調達計画（現状と方針）

**現状、リポジトリのアセットは本作に流用しにくい。** 既存は森・モンスター・勇者
（`karsiori`, `Enemy Galore`, `Pixel Monster Pack`, `Hero Knight`）と宇宙3D
（`kenney_space_kit`）で、**戦闘機・戦艦・海・空の2D素材が無い**。専用調達が要る。

パイプラインは既存ゲーム踏襲（curated PNG を `assets/gunship/sprites/` に選抜し、
`gunship.ts` で `const SPR = '/assets/gunship/sprites/'` として参照）。

| 素材 | 調達方針の候補 |
|---|---|
| 自機（戦闘機） | Kenney "Pixel Shmup" / "Tiny Battle" 等の航空機スプライト、または専用作成 |
| 戦艦・砲塔 | Kenney "Pixel Shmup"（艦船）／ naval 系ピクセルパック。無ければ簡易ジオメトリで暫定 |
| 空中の敵 | Kenney シューティング系 enemy スプライト |
| 弾・爆発・炎 | Kenney "Particle Pack" / 汎用 shmup FX。推力炎は自前パーティクルでも可 |
| 空・海・雲 | パララックス背景パック、または単色グラデ＋プロシージャル波で自前生成 |

**暫定戦略**：MVP段階は**プロシージャル／ジオメトリ描画**（三角形の機体、矩形の艦体、
グラデ空、サイン波の海面）で物理とジレンマの手触りを先に固める。見た目の完成度は
その後スプライトに差し替えて上げる。＝「物理が面白い」を絵の調達がボトルネックに
しない。ライセンスは各パックを確認し、`assets/<pack>.meta` 慣習に従い出典を記録する。

### カメラ・フレーミング

- 基本は**固定画面**（RL Arena 同様、観測が縦横比に依存しない）。海面と天井が常に
  画面内にあり、高度リソースが常時可視。
- 任意で**縦方向のソフト追従**：機体が上下に大きく動くとき僅かにカメラが追い、
  それでも海面ラインは画面下部に見え続けるようにする（境界の常時可視は死守）。
- 撃墜・撃沈の瞬間だけ極短いスローや軽い画面シェイク。多用しない（ドキュメンタリー基調）。

## UI・観察性

HUDは絵の補助。数値は画面端に寄せ、戦場の中央は物理描画に明け渡す。

- **高度マージンメーター（主役ゲージ）**：画面左端の縦リボンに「安全域／危険域／
  落下域」を色帯で表示し、現在高度と落下予測ラインを重ねる。本作で唯一常時凝視する計器。
- 下向き交戦可能フレームの残量（＝「あと何フレーム撃てるか」）を小さく可視化。
- 通常HUD：現在 Wave、HP、取得済み強化アイコン。
- 学習パネル（折りたたみ可）：命中率（戦艦/空中機別）、落下死率、下向き滞在時間、
  バースト＆リカバリーのサイクル長の推移グラフ。
- 演出はドキュメンタリー的リアリズムを踏襲。フローティングスコア・過剰フラッシュは
  避け、機体の姿勢・推力炎・弾道・海面そのもので状況を読ませる。

## 技術・実装計画

CLAUDE.md のルールに従う：

- 新規ソースは全て TypeScript（`.ts`）。`apps/gunship/` 配下に配置。
- エントリポイントを `vite.config.ts` の `rollupOptions.input` に追加。
- 同じく `tsconfig.json` の `include` に追加（型チェック対象）。
- Three.js を使う場合は名前付き import（`import { ... } from 'three'`）。型のみは `import type`。
- `main.ts` にページキー（例 `gunship`）とショートカットを追加。

### プロトタイプ段階の最小目標（MVP）

見た目は**プロシージャル／ジオメトリ先行**で作り、物理の面白さをアセット調達で
止めない。スプライト化は手触りが固まってから。

1. 重力＋機首方向推力の物理を実装（推力ONで旋回低下・TWR可変）。描画は三角形の機体・
   グラデ空・サイン波の海面で可。**推力炎と機首角だけは最初から描く**（物理の可読性）。
2. 海面境界（落下死）と1種類の戦艦・1種類の空中機を矩形/簡易形状で置く。
3. **スクリプト化テストパイロット**（単純ヒューリスティック）で CLIMB→照準→BURST→
   RECOVER が回るかを確認し、TWR・`turnRate`・`g` を数値ログでチューニングする。
   （手動プレイは前提にしない — 挙動確認は自動エージェントとログで行う。）
4. 高度マージンメーターと危険ビネットを最初から入れる（観察性が本作の主目的）。
5. Tabular Q（Stage A）で「落ちずに撃つ」を学習できるか確認。落下死率が下がるかを見る。
6. 手触りが固まったら `assets/gunship/sprites/` にスプライトを差し替え、パララックス
   背景・爆発/水柱FX・アニメ波でビジュアルを仕上げる。

## 検証条件（このゲームが成立しているかの判定）

- 見ているだけで「今この機体は攻めているのか、高度を立て直しているのか」が、
  **HUDを見ずに機体の姿勢・推力炎・海面との距離だけで**分かるか。
- 高度を下げたときに画面が視覚的に「重く・危険に」なるか（色・ビネット・海面の占有）。
- 学習が進むと「下向き滞在時間が伸び／落下死率が下がる」など、上達が指標に出るか。
- モデル世代で操縦リズムに差が見えるか（臆病なモデル／大胆なモデル）。
- 放置しても Wave と学習が進み続けるか。

以上を満たさない場合、重力ジレンマ・観測・報酬のどれが弱いかに立ち返る。
