## コンセプト一行

**1本のラインの上で、強化学習エージェントが敵の波を捌きながら「戦い方を覚えていく」過程を眺める観戦バトル。
攻撃は"コミット（長い動作＋硬直）"で、正しい間合い・正しいタイミングでしか当たらない。
だからAIは最初は下手で、学習して初めて勝てるようになる——その上達を眺めるのが遊び。**

### 主軸の確認

このゲームの主目的は**操作ではなく観察**（シリーズ方針通り）。プレイヤーのキー入力は
任意の上書きに留め、コアは「**Q学習エージェントが戦闘を学習する様子の可視化**」に置く。
評価軸は次の4点：

1. 🎯 **"なんとなく"では勝てないか**（間合い・タイミングを守らないと成立しない戦闘の骨格）
2. 👁 **アクションと攻撃範囲が目で読めるか**（アセットで隙・射程・硬直を明示）
3. 🧠 **AIの学習・判断が可視化されているか**（なぜその行動を選んだか、どう強くなったか）
4. ♾ **放置しても変化が続くか**（学習の積み上げ・戦況の多様化）

### 設計上の最重要原則（今回の改善の起点）

現プロトタイプ最大の問題は **「連打・接近でなんとなく倒せてしまう」** こと。これだとAIが
学ぶべき技術が存在せず、学習の可視化も無意味になる。そこで次を土台に据える：

- **攻撃はコミットする** — 各アクションに `予備動作 → 有効 → 硬直` の3フェーズを持たせ、
  硬直中は動けず被弾が増える（＝**隙**）。連打すると硬直を狩られる。
- **間合いが要る** — 攻撃には有効射程があり、外す(whiff)と当たらないまま硬直だけ残る。
- **タイミングが要る** — 敵の攻撃予備 → 硬直に生まれる**隙**を突いて、初めて安全に殴れる。
- **これらを目で見せる** — 射程・隙・硬直を**アセット/描画で明示**しないと、観察者にもAIにも
  「良いタイミング・良い距離」が伝わらない。可視化は演出ではなく戦闘設計の一部。

流れ：**待つ → 敵の隙を読む → 正しい間合いに詰める → コミット攻撃 → 自分の硬直を安全に抜ける**

### 現状の課題

1. **学習の可視化が薄い** — EPSILON・STATES数は出るが、「今なぜこの行動を選んだか（Q値）」
   「学習が進んでどれだけ上達したか（トレンド）」が観察者に伝わらない。観戦価値の核が欠けている。
2. **強化選択が無意味化** — ウェーブ間の選択が2.5秒で `power` 自動固定。観察上も意思決定に見えない。
3. **成長の記憶がない** — Q-table未永続化。放置観察の価値（積み上げ）が発生しない。
4. **戦況が単調** — 敵3種・1ライン固定。長時間観察で変化に乏しい。
5. **`learning_hud.ts` が空同然** — 1秒ごとに status 文字を戻すだけ。

## 戦闘の骨格リデザイン ★最優先の土台

「なんとなく勝てない」を成立させるコア。可視化・学習の**前提**なので最初に作る。

### 1. アクションのフェーズ化（コミットと隙）

各アクションを固定の3フェーズで表現する。フェーズ中は他行動へ移れず、硬直中は無防備。

| フェーズ | 内容 | 被弾 |
|---------|------|------|
| 予備動作 (startup) | 攻撃の振りかぶり。この間に踏み込む/離脱はできない | 通常 |
| 有効 (active) | 判定が出る数フレーム。射程内の敵にのみヒット | 通常 |
| 硬直 (recovery) | 動けない**隙**。長いほどハイリスク | **増加**（狩られる） |

例（数値は初期案・要調整）：

| 行動 | 予備 | 有効 | 硬直 | 有効射程 | ダメージ | 特徴 |
|------|------|------|------|---------|---------|------|
| light | 短 | 短 | 短 | 近(〜70px) | 低 | 小回り。詰めてすぐ抜ける |
| heavy | 長 | 中 | 長 | 中(〜120px) | 高 | 隙が大。確定反撃向き |
| special | 長 | 中 | 最長 | 広(範囲) | 最高(SP消費) | 大隙。多数の敵の隙にだけ |
| guard | 即 | 持続 | 短 | — | 0(被ダメ減) | スタミナ消費。守りのコミット |
| jump | 即 | 滞空 | 着地隙 | — | 0(回避) | 地上判定を避ける |

### 2. 間合い（スペーシング）の必須化

- 攻撃は**有効射程の内側でしか当たらない**。射程外で振ると whiff（空振り）＝ヒット無しで硬直だけ残る。
- whiff は**明確にペナルティ**（報酬マイナス＋硬直を狩られやすい）。→ 距離を合わせる動機が生まれる。
- back / forward は「間合い調整」の行動として、フェーズの合間に差し込む必要がある。

### 3. タイミング（隙の奪い合い）

- 敵も `予備動作 → 攻撃 → 硬直` を持つ。敵の硬直＝**こちらの確定反撃チャンス**。
- 敵の予備動作中に踏み込む/離脱を誤ると被弾。telegraph は「今動くな／今詰めろ」の信号。
- 良い流れ＝**敵の隙 × 自分の射程 × 攻撃の有効フレーム**が三つ揃った瞬間に殴る。

### 4. 報酬の再設計（技術を学ばせる）

現行の「当たれば加点」から、**タイミングと間合いを評価**する形へ：

- 敵の硬直中に射程ぴったりでヒット → **大きく加点**（狙った反撃）
- whiff（射程外で空振り）→ 減点（無駄な隙）
- 自分の硬直を敵に狩られた → **大きく減点**（コミットの失敗）
- 敵の予備動作に反応してガード/回避成功 → 加点
- 連打で硬直を重ねる → 実質マイナス（狩られるため自然に）

これにより Q学習は「待つ→間合い→隙に差す」というポリシーへ収束していき、その過程が観察対象になる。

### 5. 観測(Obs)の拡張

タイミング・間合いを学べるよう観測次元を追加：

- `enemyPhase`（敵の 予備 / 攻撃 / 硬直 / 無し）— 反撃チャンスの識別
- `selfPhase`（自分が 硬直中か 行動可能か）— 隙の自覚
- `inRange`（射程内か、どの攻撃が届くか）— 間合いの離散化
- 既存の distance は「射程バンド」として粗く保持

## 改善設計

観察主軸に沿い、上記の**戦闘骨格**を土台に、**「アクションが見える／学習が見える／積み上がる／飽きない」**
の4本柱で改善する。優先度は 骨格 ＞ V（アクション可視化）＞ A（学習可視化）＞ B（永続化）＞ D ＞ C。

### V. アクション・攻撃範囲の可視化 ★骨格と同時に必須

間合い・隙を観察者とAIが**目で読める**ようにする。アセットで見せることが必須要件。

- **V1. 攻撃範囲の明示** — 各攻撃の有効射程を、発動時にアーク/ゾーンで描画。whiff は範囲が届いて
  いないことが一目で分かる。敵の攻撃範囲も同様に予告表示。
- **V2. フェーズの視覚化** — 予備動作＝溜めポーズ＋予兆色、有効＝フラッシュ/斬撃エフェクト、
  硬直＝無防備ポーズ＋隙インジケータ。3フェーズが見て区別できること。
- **V3. アセット導入（最初から）** — ベクター矩形は使わず、**P0+P1の初手からCC0スプライトを導入**する
  （decision 2026-07-28）。`assets/one-line-rpg/README.md` 記載のCC0パック（Kenney Abstract Platformer /
  OpenGameArt CC0 Creatures）を取得・配置し、idle / move / attack(予備・有効) / recovery / hit / defeat の
  ステートをスプライトで用意。フェーズ（予備/有効/硬直）はスプライトの差し替えで表現する。
  ※ zipパックの取得はリポジトリへの配置が必要。取得手段が無い場合はプレースホルダのスプライトシートを
    生成して先に構造を組み、後で正規アセットに差し替える。
- **V4. 間合いガイド** — ライン上に「light届く／heavy届く」の距離目盛を薄く表示し、
  AIがどの間合いを取っているかを可読化。

### A. 学習の可視化

「AIが賢くなっていく様子」を画面から読み取れるようにする。骨格・アクション可視化の上で意味を持つ。

- **A1. 行動Q値の可視化** — 現在の状態に対する8行動のQ値を横バーで常時表示。
  選択された行動をハイライトし、探索(exploratory)時は色を変える（活用＝青系／探索＝黄系）。
  `TabularQAgent.valuesForState()` と `decide()` の `exploratory` フラグを使う。
- **A2. 上達トレンド** — ウェーブごとの「生存時間 / 撃破数 / 被弾数」を折れ線ミニグラフで蓄積。
  「学習して上手くなる」曲線が観察者に見える。
- **A3. 判断の言語化** — telegraph検知→回避、間合い詰め→攻撃、などの意図を1行テキストで表示
  （現 status 行を活かして `learning_hud.ts` に実装）。
- **A4. 状態空間の成長** — STATES（既知状態数）とEPSILONの推移を、数値だけでなく小さなゲージで。

### B. 学習の永続化

放置観察の価値を跳ね上げる。

- **B1. localStorage 接続** — `serialize()`/`restore()` を localStorage に接続。
  一定間隔（例: ウェーブクリア時）で保存、起動時に復元。
- **B2. 学習リセットUI** — 観察をやり直したいとき用に、明示的なリセットボタン（任意）。

### D. 強化選択のAI化

ウェーブ間の強化選択を「AIの意思決定」として見せる。

- **D1. 自動`power`固定を廃止** — HP/SP/戦況に応じてエージェント自身が選ぶ
  （簡易ヒューリスティック、または選択自体を報酬に接続した別軸の学習）。
- **D2. 選択理由の表示** — 「HPが低いので休息を選択」等を1行で提示。

### C. 戦況の多様化

長時間観察で飽きさせない変化。優先度は最後（コア可視化が先）。

- **C1. 敵バリエーション拡張** — 現3種に加え、稀に混成波・高速波など。
- **C2. ボスウェーブ** — 数ウェーブごとに大型敵。学習が試される山場を作る。
- **C3. 地形/ライン演出** — 背景・ラインに時間帯や区間の変化を足す（描画のみ、ロジック非依存）。

## 非目標（やらないこと）

- 人間プレイヤー前提の操作性強化（難易度カーブ調整、コンボUI強化など）。主軸は観察。
- フローティングスコアや過剰なフラッシュ演出（シリーズの「宇宙ドキュメンタリー」的リアリズムに反する）。
- 3D化・大規模アセット導入（軽量Canvasの即応性を優先。README記載のスプライト差し替えは任意の後日課題）。

## 実装メモ

- 全新規ソースは TypeScript（`.ts`）。エントリは `vite.config.ts` の `rollupOptions.input` と
  `tsconfig.json` の `include` に追加済みか要確認。
- Three.js は不要（Canvas 2D）。可視化はDOM/CanvasどちらでもよいがHUDはDOM（既存 `.panel`）を踏襲。
- 可視化ロジックは `learning_hud.ts` に寄せ、`one_line_rpg.ts` のゲームループから状態を渡す構成にすると
  コアと表示の責務が分離できる。
